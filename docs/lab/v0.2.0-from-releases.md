# `v0.2.0` — la publication du renommage, mesurée depuis la page Releases

## Statut

Preuve exécutée le 21 août 2026 par
[`tests/lab/v0.1.3/from-releases/prove`](../../tests/lab/v0.1.3/from-releases/prove),
machines `lab-vps` (le poste) et `lab-machine-1` (le serveur), topologie
`quick`.

**Le parcours aboutit depuis la page, sans écart.** Un inconnu qui suit
littéralement ce que la page `v0.2.0` publie télécharge, vérifie, installe et
obtient `VERIFIED` ; puis « Créer une infrastructure » mène à « Le Controller
est actif sur la machine. » en **34 secondes**.

`ECARTS_README=0` : les quatre commandes lues dans le README publié suffisent,
aucune commande de secours. C'est le premier rejeu de cette preuve où l'oracle
ne mesure aucun écart — la `v0.1.3` en avait relevé six, dont deux bloquants
que `#150` et `#157` ont levés.

Cette passe mesure une **publication de renommage** : le périmètre fonctionnel
de la `v0.2.0` est celui de la `v0.1.4`, et ce rapport ne le rejuge pas. Ce
qu'il établit, c'est que le renommage n'a rien cassé sur le trajet public.

## Les quatre commandes du README, jouées sur une machine nue

L'oracle **lit** les commandes dans le README publié et les joue dans son
ordre, sur `lab-vps` nue.

| # | commande | code | durée | résultat |
|---|---|---|---|---|
| 1 | `sha256sum your-cloud_0.2.0_amd64.deb` | 0 | 0 s | `d21cd310…7459`, concordant |
| 2 | `sudo apt update` | 0 | 1 s | — |
| 3 | `sudo apt install ./your-cloud_0.2.0_amd64.deb` | 0 | 1 s | `Setting up your-cloud (0.2.0)` |
| 4 | `--verify-embedded-server-bundle` | 0 | 0 s | `VERIFIED version=0.2.0` |

Le verdict complet de la quatrième :

```
VERIFIED version=0.2.0 target=debian-13-amd64 size=6081412 \
  sha256=60952b0a5cdcf1d6ca0c163fabdd0114d121071c73eee1687e7193dc45ee9e6f
```

**Le nom du paquet Debian n'a pas changé** : `dpkg` pose `your-cloud (0.2.0)`,
comme la `v0.1.4` posait `your-cloud (0.1.4)`. Seuls le binaire et le
répertoire du lot ont suivi le renommage.

Constaté sur `lab-machine-1` par des commandes du système, pas par ce que le
produit déclare.

```
ii  your-cloud-server 0.2.0  amd64  Your Cloud server binary and its static unit definitions
```

| | |
|---|---|
| unité | `active`, `Type=notify`, `NRestarts=0`, `ExecMainStatus=0` |
| `your-cloud-controller.service` | active, enabled |
| `your-cloud-daemon.service` | inactive, disabled |
| `your-cloud-relay.service` | inactive, disabled |

Une seule unité du produit est active : le Controller. Le Daemon et le Relay
restent à l'arrêt, comme le palier le prévoit.

**Un résidu, connu et ouvert** : `/home/inconnu/.your-cloud-bootstrap`, le
répertoire d'attente que
[`#156`](https://github.com/ldesfontaine/your-cloud/issues/156) porte. Un
second parcours sur la même cible exige aujourd'hui de le retirer à la main.
Le renommage ne l'a ni créé ni aggravé.

## Reproduire

```bash
tests/lab/v0.1.3/from-releases/prove all
```

Le poste se rend à son état nu par `tools/labctl revert lab-vps vierge`, et la
phase `remove` a rendu le serveur : `SERVEUR_RENDU_OK`.

Artefacts : `tests/artifacts/proofs/from-releases/20260821T175216Z-422976/`
(locaux à la machine de preuve, `proofs/` n'est pas suivi par git).

## Ce que cette passe ne prouve pas

- **Qu'un humain ait lu quoi que ce soit** : les instruments attestent ce que
  les commandes rendent, pas ce qu'un lecteur comprend.
- **Que le `.deb` soit reproductible** : il ne l'est pas. Le lot serveur
  embarqué l'est — reconstruit à l'identique dans le LAB et dans le conteneur
  `debian:13` de la porte hébergée — mais l'empaquetage Debian de l'App rend
  deux empreintes différentes pour une même révision. L'empreinte publiée vaut
  pour le fichier joint à la page, et pour lui seul.
- **Que la reprise d'un coffre de `v0.1.4` fonctionne** : elle n'existe pas. Le
  dossier de données passe de `fr.your-cloud.console` à `fr.your-cloud.app` et
  le compartiment du coffre avec lui ; l'App démarre comme à sa première
  ouverture. La page le dit.
- **Le périmètre fonctionnel de la `v0.1.4`** : il n'est pas rejugé ici. Sa
  mesure reste [`v0.1.3-controller-install.md`](v0.1.3-controller-install.md).
- **Le chemin de commande complet** (App → Relay → Controller), qui appartient
  aux paliers suivants.
