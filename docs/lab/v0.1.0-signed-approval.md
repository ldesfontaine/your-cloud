# `v0.1.0` — approbation signée vérifiée sans faire confiance au Controller

## Statut

Implémentation et preuves de l'issue `#37` **exécutées** le 5 août 2026 dans le
LAB, sur `lab-console` et `lab-machine-1` de la topologie `quick`. Le cœur natif
de la Console signe une enveloppe canonique versionnée ; l'Auxiliaire de
diagnostic la vérifie localement, la consomme une seule fois et refuse tout le
reste, y compris après un **redémarrage réel** de la machine cible.

Ce palier ne prouve **aucune** mutation. L'Auxiliaire est en diagnostic de
protocole, strictement en lecture seule, et son rapport porte `changed: false`
comme une constante. Aucune réussite enregistrée ici n'est une première action
OCI. La commande forcée SSH qui lancera l'Auxiliaire appartient à `#54`, et la
fenêtre de confirmation native qui doit précéder une émission réelle appartient
au palier qui ajoutera la commande d'approbation.

## Ce que la signature lie

L'enveloppe est écrite une seule fois, sous un séparateur de domaine propre, et
chaque valeur de longueur variable est écrite sous sa propre longueur en gros
boutiste. Les champs liés sont, dans cet ordre exact :

| Champ | Forme | Pourquoi il est dedans |
|---|---|---|
| `schema_version` | 1 octet | une version future ne se lit pas comme celle-ci |
| `infrastructure_id` | UUIDv4 canonique | une approbation d'une autre infrastructure n'est pas la nôtre |
| `machine_id` | identifiant produit | une approbation ne vaut que pour une machine |
| `approval_epoch` | entier 64 bits | une époque remplacée n'a plus d'autorité |
| `sequence` | entier 64 bits | seul le successeur exact est accepté |
| `operation` | nom fermé | la table des opérations est positive |
| `plan_sha256` | 32 octets | le plan approuvé, pas un autre |
| `rollback_sha256` | 32 octets | un retour non approuvé serait un retour non couvert |
| `privileges` | compte puis noms triés | un privilège ajouté change les octets |
| `issued_at_unix_seconds` | entier 64 bits | l'émission borne la fenêtre |
| `expires_at_unix_seconds` | entier 64 bits | une approbation ne vit pas indéfiniment |
| `approval_public_key` | 32 octets | l'enveloppe nomme le signataire attendu |

La signature Ed25519 couvre exactement ces octets. Elle est calculée par le cœur
natif de la Console à partir de la clé humaine de l'association ; l'Auxiliaire la
reconstruit depuis les champs qu'il a analysés, jamais depuis le document reçu.
Un Controller peut donc réindenter ou réordonner le JSON — c'est le même
document approuvé — mais il ne peut changer aucune valeur.

### Incident de disque

`lab-console` a atteint 100 % de `/` pendant l'édition de liens du binaire de
test du paquet Console : `rust-lld` s'est arrêté sur `Bus error`. Le cache
`target/debug/deps` n'a pas été touché ; ont été retirés le cache APT, le
journal, `target/debug/incremental`, et les trois artefacts régénérables du
crate Console lui-même (`libyour_cloud_console.{a,so}`, 953 Mio à eux deux).
`/root/.cargo/registry/cache` a également été retiré, ce qui a cassé le mode
`--offline` : la suite Console a donc été exécutée sans `--offline`, avec
re-téléchargement des archives `.crate` déjà épinglées par `Cargo.lock`. C'est
un fait d'outillage, pas du produit, et il est consigné pour rendre le passage
rejouable.

## Vecteurs déterministes Console / Auxiliaire

Un vecteur unique est épinglé des deux côtés, depuis une graine synthétique
tout-`0x01` qui n'est jamais une clé réelle :

| Élément | Valeur |
|---|---|
| Clé publique | `iojj3XQJ8ZX9UtstPLpdcspnCb8dlBIb83SIAbQPb1w` |
| Longueur de la transcription | 285 octets |
| Signature | `rmoKkEc47JjAkPMXv_0q_Qgust3FNKoOlwDc8eajMpsWl6LqB6phBnPkR-CaMNpkm4X0oH_Gg-6CrVczUL6zCg` |

Les 570 caractères hexadécimaux de la transcription sont écrits dans
`crates/bootstrap-protocol/src/approval.rs`, dans `src/approval.rs` pour la
signature produite par le cœur natif, et dans `internal/approval/envelope_test.go`
côté Auxiliaire. La signature produite par la Console est **vérifiée par le code
Go** dans son propre test. Un encodeur qui dérive d'un seul octet rougit donc
sur l'un des deux côtés au lieu de produire une approbation que l'autre refuse
silencieusement sur une machine réelle.

## Redémarrage réel

Le harnais versionné
[`tests/lab/v0.1.0/signed-approval/prove`](../../tests/lab/v0.1.0/signed-approval/prove)
monte le périmètre, exécute la matrice complète, **arrête et redémarre
`lab-machine-1` par le contrôleur du LAB**, rejoue les refus, puis retire le
périmètre et prouve son absence.

Les quatre enveloppes présentées après le redémarrage sont signées **avant**
l'arrêt de la machine : rien de produit après le cycle d'alimentation ne peut
expliquer un refus. Le condensat SHA-256 de l'état anti-rejeu est pris avant
l'arrêt et vérifié après le démarrage.

| Observation | Résultat |
|---|---|
| Position avant l'arrêt | époque 1, séquence 3, SHA-256 `9b052d9f…98bab` |
| Machine après démarrage | `uptime` 6 s |
| Position retrouvée | identique octet pour octet |
| Séquence 3 rejouée | refusée : `is not the exact successor of 3` |
| Séquence 1, plus ancienne | refusée : `is not the exact successor of 3` |
| Séquence 5, sautée | refusée : `is not the exact successor of 3` |
| Séquence 4, successeur exact | acceptée, `changed=false` |
| Séquence 4 rejouée aussitôt | refusée : `is not the exact successor of 4` |

Ce que ce redémarrage prouve : l'état anti-rejeu est une position durable sur
disque, écrite par `fsync` puis `rename` puis `fsync` du répertoire, et non une
mémoire de processus. Un rejeu après coupure d'alimentation est refusé pour la
même raison qu'avant.

## Verrouillage après récupération, et rotation

| Observation | Résultat |
|---|---|
| Console récupérée avec une nouvelle clé humaine, ancre inchangée | refusée : `signed for a key this machine does not anchor` |
| Rotation de l'ancre par `root` sur la machine, nouvelle époque | acceptée à la séquence 1 |
| Nouvelle époque continuant l'ancienne série | refusée |
| Ancienne autorité après la rotation | refusée : `names another authority epoch` |

Ce que cela établit : le Controller ne peut pas lever ce verrou. Ce qui le lève
est le remplacement d'un fichier `root`, installé par l'Assistant à travers
l'accès SSH personnel, machine par machine. Activer une nouvelle époque invalide
l'ancienne au lieu de maintenir deux signataires.

## Refus exercés avant le redémarrage

Chaque refus est vérifié **par sa raison**, pas seulement par un statut non nul,
et chacun est encadré par le contrôle positif qui isole sa seule différence.

| Cas | Refus observé |
|---|---|
| Séquence 2 sur une machine qui n'a rien consommé | `is not the first of a machine that consumed none` |
| Séquence rejouée | `is not the exact successor of 1` |
| Séquence sautée | `is not the exact successor of 1` |
| Autre machine | `names another machine than this one` |
| Autre infrastructure | `names another infrastructure` |
| Autre époque | `names another authority epoch` |
| Clé humaine non ancrée | `signed for a key this machine does not anchor` |
| Privilège mutant | `requires exactly its own privileges` |
| Opération inconnue | `is not one this Auxiliary performs` |
| Approbation expirée | `has expired` |
| Approbation pas encore valide | `not valid yet` |
| Séquence, machine, époque ou rollback réécrits en transport | `signature does not cover this envelope` et les liens d'ancre |
| Deux consommations au même instant | `already being consumed` |
| Auxiliaire sans autorité `root` locale | `requires local root authority` |

contrat avec son propre message.

## Ce que ce passage ne prouve pas

- **aucune mutation**, sur aucune machine, par aucun chemin ;
- aucune commande Tauri n'émet d'approbation : le module de signature du cœur
  natif n'est atteint par aucune commande enregistrée, et le contrat de sources
  refuse qu'une telle commande apparaisse sans sa fenêtre de confirmation ;
- l'installation de la commande forcée SSH et l'invocation de l'Auxiliaire à
  travers elle restent à `#54` : ici l'enveloppe est présentée sur l'entrée
  standard d'un processus lancé localement en `root` ;
- le signataire employé par le harnais LAB est une **fixture synthétique** qui
  réécrit la même transcription canonique, pas le binaire de la Console.
  L'interopérabilité réelle entre les deux implémentations est prouvée par le
  vecteur épinglé, où la signature produite par le code Rust est vérifiée par le
  code Go ;
- aucune clé réelle, aucune infrastructure réelle et aucun secret réel n'ont été
  employés ; toutes les graines sont synthétiques et constantes.

## Nettoyage

`tests/lab/v0.1.0/signed-approval/prove remove` a retiré l'ancre, le répertoire
anti-rejeu, les deux binaires et l'état du harnais, et a prouvé leur absence.
Les deux machines Linux restent démarrées ; `lab-windows` n'a jamais été
allumée.
