Une future découverte reste en lecture seule et limitée aux machines enrôlées. Ni le Daemon, ni le Relay, ni l'App ne scannent le LAN ; la présence sur le même réseau ne donne aucune confiance.

File provider retenu

  • Routes explicitement écrites
  • Aucun socket Docker
  • Fonctionne pour un conteneur ou une machine distante
  • Un service inconnu reste invisible

Docker provider écarté en V1

  • Observe les événements du moteur
  • Lit les labels des conteneurs
  • Exige l'accès à l'API Docker
  • Augmente l'impact d'un Traefik compromis

Limite : le file provider ne corrige pas une mauvaise route approuvée et n'empêche pas une vulnérabilité de Traefik. Il réduit l'autorité du proxy ; il ne remplace pas les tests ni le filtrage réseau.

Podman, Docker et Quadlet

ÉlémentExplication simplePoint de vigilance
Image OCILe paquet standard contenant le service et ses dépendances.Digest, provenance et vulnérabilités.
DockerUn moteur très répandu, généralement organisé autour d'un démon.Le mode rootless existe ; le socket donne une autorité importante.
PodmanLe moteur OCI retenu, sans démon central et utilisé rootless ; sa CLI est comparable à Docker.Pas magiquement sûr : réseau, volumes et capacités restent à borner.
QuadletLa fiche déclarative retenue, transformée par systemd en service Podman.OWASP ne l'impose pas : chaque réglage doit appliquer et prouver un contrôle concret.

Limite V1 : ce parcours exige systemd et cgroup v2 sur l'hôte. L'App les vérifie avant mutation et refuse sinon le déploiement OCI géré ; aucun repli OpenRC ou runit n'est inventé. Un service installé autrement peut rester externe. Les prérequis du seul Daemon seront décidés séparément.
